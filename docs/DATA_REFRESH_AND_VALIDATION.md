> 目前 GitHub Pages 僅提供靜態 HTML、既有 Excel 快照。正式版需獨立後端及資料庫，且不可將任何 API token／客戶個資放在此公開 repository。

## I. 資料架構

1. `instruments`（instrument_id、名稱、ISIN、ticker、市場、基金級別、幣別、累積／配息類別、存續狀態）。
2. `price_nav_raw`（instrument_id、local_date、value、currency、source、provider_timestamp、retrieved_at、版本）。
3. `corporate_actions`（ex_date、record_date、pay_date、每單位配息、幣別、拆分／反分割、資本返還、來源）。
4. `price_nav_adjusted`（原始價格、還原處理類別、計算版本、可追溯來源），**不改寫原始值**。
5. `data_quality_checks`（每檔起訖日期、預期交易日、缺漏日期、重複筆、異常變動、更新延遲、檢查時間）。

## II. 更新作業（尚未啟用）

1. 依來源授權與使用條款，按市場交易日批次取得台股／ETF，境內外基金按發布時差與 T+1 規則擷取 NAV。
2. API 密鑰僅存於伺服器端 Secret／環境變數，**不得提交 GitHub 或暴露在瀏覽器**。
3. 入庫前檢查 `instrument_id + date + source + share_class + currency`、時間戳、數值合理性、缺漏與分割事件。
4. 新版本走 staging；比對、審查、發布後才供前端使用；失敗即沿用上次已驗證版本，並醒目標示截止日。
5. 記錄 provider、更新時間、失敗原因、上次成功同步時間；前端顯示每檔日期與警示，不將靜態快照標成即時。

## III. 含息報酬與回測驗證

- 先釐清來源 NAV 是否已還原配息或價格拆分，以防重複加回。
- 區分「純價格報酬」「現金配息」「含息總報酬」與「配息再投入」，定義換匯日、費用與稅費。
- 與原始 Excel 逐筆對帳：840 筆固定 OLS、殘差 SD、Z-Score、五線譜及六策略交易序列。
- 不能只以期末價值比較投入額不同的策略；驗證 XIRR、CAGR、MDD、Sharpe、資金使用率等。

## IV. 客戶資料安全（正式版）

- 資料庫與 API 應建立帳戶隔離（例如 RLS／伺服器端授權），GitHub Pages 只存放**公開**前端資產。
- 管理者、投資客戶採最小權限，保存稽核事件，測試資料與正式資料分離。
- 此 repo 不存客戶身份、持倉、登入憑證或未公開商業資料。
