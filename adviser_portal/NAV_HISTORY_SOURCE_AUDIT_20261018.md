# 三年以上基金歷史 NAV：資料來源稽核與試用版（2026-10-18）

## 本階段範圍

已增加「**檢查三年以上歷史 NAV**」按鈕，適用境內及在台核備境外基金。僅人工點按時讀取目前 SITCA/TDCC 近期公開 NAV，不會自動匯入、保存完整價格歷史、計算報酬或接入正式配置。

- 境內：先由 SITCA 當期每單位 NAV 核對基金名稱＋代碼＋幣別（若 ISIN 存在亦須核對）。
- 境外：由 TDCC `3-2` 基金級別基本資料及 `3-4` 近七日淨值核對完整名稱＋代碼＋ISIN＋幣別。
- **兩個來源都不能直接宣稱已有三年完整歷史**。不能把過去三年的走勢圖、近七日資料、三年累積報酬、基金淨值小計當作完整逐日原幣每單位 NAV。
- API `GET /api/history-coverage?uid=<公開基金UID>` 僅回覆來源識別、近期 NAV 日期筆數、三年前所需起始日和缺漏事項，永遠不回覆推估三年績效；股票/ETF 不走基金 NAV 模組。
- 不收集或儲存顧客與真實配置，僅用公開代碼與身分。

## 離線歷史資料驗證器

可用的受控命令：

```bash
python -m adviser_portal.nav_history_audit --manifest /private/<share-class>.json --csv /private/<raw-history>.csv --sessions /private/<issuer-nav-dates>.json
```

離線驗證器不會出現在公開網站的上傳欄位；此路徑供日後從基金公司或合法授權供應商取得原始資料後，進行核對。原始檔不能提交公開 GitHub，也不能混用客戶上傳資料。

1. 每份歷史原檔需要**一個完整基金級別 ISIN**、單一原幣幣別，且欄位為 `nav_date,isin,currency,nav_per_unit`。拒絕混用含息淨值、總額、其他級別、特殊幣別與非正值 NAV。
2. 文件清單（manifest）要求公開提供者名稱、HTTPS 原始來源、授權／合法商業使用的人工核准旗標、原始檔 SHA256，並以程式重新計算比對，不接受偽造的摘要。
3. 資料必須跨度至少三年。以 2026-10-18 為例，需要起始日 **不晚於 2023-10-18**；不要求週末／假日每日都有 NAV，但必須有相同級別經複核的**基金實際估值日清單**。自動用「平日」推算完整度是不正確的。
4. 原始歷史 CSV 與日期證據清單分開計算雜湊；重複日、同日不同 NAV、證據日缺漏、額外未知日期、來源日期大幅過期都會列為阻擋條件。
5. 日曆與授權旗標目前只是本地**提交者／審核者聲明**，程式尚未對外部官網文件建立獨立法律／日曆驗證流程；即使結果顯示 `PROVISIONAL_HISTORY_SOURCE_COVERAGE_ONLY`，仍**不是基金含息績效核准**。尚需按級別核對歷史配息、再投入時點、基金拆併、費用與歷史匯率；再對照 Excel 27 張表公式。
6. 研究資料稽核輸出只包含來源 SHA、級別、日期跨度、缺漏筆數與品質旗標，不公開逐筆 NAV 數字。不存入 Neon、不修改正式網站或策略。

## 目前實際狀態

- 已完成稽核器與前端按鈕的合成資料測試；**不是全市場歷史 NAV 回補**。
- TDCC/SITCA 近期資料只用來顯示目前能核對的近期日期筆數；目前 **完整三年原始歷史資料正式匯入量 0 筆**。因尚無經授權的歷史 NAV 原檔與經審核的實際估值日曆，暫不能定義任何基金的三年來源覆蓋率。
- 除息／每單位配息／原幣入帳與再投入 NAV、含息年化、三年累積／最大回撤、台幣匯率、原 Excel 完整移植，均未開啟。
